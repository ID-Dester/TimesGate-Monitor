# Network text proof of concept

## Цель

Проверить, может ли Times Gate менять показатели без полной повторной загрузки JPEG. Для этого используется `Draw/SendHttpItemList` с network-text элементами типа `23`.

## Как это работает

Приложение запускает Kestrel только на LAN-адресе ПК и отдаёт:

- `/background/cpu.gif` — статичный консольный фон;
- `/value/cpu-load` — JSON `{"DispData":"47%"}`;
- `/value/cpu-bar` — JSON со шкалой `[■■■■■□□□□□]`;
- `/value/cpu-temp` — JSON `{"DispData":"48C"}`.

Times Gate получает фон один раз, затем самостоятельно опрашивает три value URL. Поэтому изменение `HardwareSnapshot` не создаёт исходящий `Draw/SendHttpGif`.

## Подтверждённые особенности этой прошивки

- `LocalToken` требуется и для `Draw/SendHttpItemList`;
- поле протокола действительно называется `BackgroudGif` с опечаткой;
- `LcdIndex` начинается с нуля;
- небольшие `TextId` 1–3 приняты устройством;
- минимальный payload без необязательного `align` принят;
- за 20 секунд устройство запросило фон 1 раз, load 10 раз, bar 9 раз и temperature 9 раз;
- фактический период опроса оказался примерно 2 секунды даже при `update_time: 1`.

Последний пункт показывает, что firmware самостоятельно ограничивает частоту. Для полной панели нужно умеренное число полей и разные интервалы, иначе слишком частые запросы могут мешать другим функциям устройства.

## Полная панель из пяти экранов

После успешного одноэкранного теста та же схема распространена на всю панель:

| Экран | Заголовок | Строки | Интервал |
|---|---|---|---|
| 1 | `GPU` | GPU load, temperature, текущая мощность (`TDP`) | 3 с |
| 2 | `CPU` | CPU load, temperature, текущая мощность (`TDP`) | 3 с |
| 3 | `CORE` | CPU load/temp, GPU load/temp, RAM used/total | 3 с |
| 4 | `RAM` | load, used/total, free | 5 с |
| 5 | `SYSTEM` | локальное время, uptime, CPU/GPU temp | 5 с |

Каждый экран получает три поля типа `23`, всего 15 полей с уникальными `TextId` 1–15. Команды настройки отправляются последовательно с паузой 1,5 секунды: это снижает риск наложения операций в небольшой очереди прошивки и устраняет замеченное ранее визуальное дублирование.

FPS исключён из пользовательской версии и модели данных и заменён локальными часами.

Реальная 40-секундная проверка полной панели завершилась без ошибок:

- все пять `Draw/SendHttpItemList` приняты;
- каждый статичный фон запрошен ровно один раз;
- устройство сделало 120 запросов значений;
- после конфигурации приложение не отправляло динамических JPEG/GIF.

Запуск 15-минутной проверки:

```powershell
.\artifacts\network-text-dashboard\TimesGateMonitor.exe --text-dashboard `
  --ip 192.0.2.181 --token REPLACE_WITH_LOCAL_TOKEN --brightness 70 `
  --serve-ip 192.0.2.159 --serve-port 8765 --duration 900
```

## Почему Kestrel

Kestrel входит в .NET 8 и не требует отдельного Python/FastAPI процесса. Он не блокирует hardware polling, корректно останавливается через `CancellationToken` и в будущем может жить внутри WPF-приложения как owned service.

Сервер привязывается к указанному `--serve-ip`, а не ко всем интерфейсам. Это уменьшает область доступа. Адрес ПК желательно закрепить в DHCP, потому что Times Gate сохраняет URL текстовых полей.

## Что проверить визуально

1. Фон появляется только при начальной настройке.
2. Процент, температура и шкала меняются без `Loading`.
3. Встроенный шрифт прошивки отображает символы `■` и `□`.
4. Подсветка и кнопки не зависают во время 15-минутной нагрузки.
5. После остановки программы значения замерзают, но экран не должен перезагружаться.

Если квадратные Unicode-глифы отсутствуют в шрифте, fallback — консольные символы `#` и `.`. Это не требует изменения протокола.
