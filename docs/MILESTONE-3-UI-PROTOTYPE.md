# Stage 2 final: configurable WPF dashboard

Статус: завершён и принят как основа для следующего этапа.

## Цель версии

Это функциональная проверка новой, более простой навигации, а не финальный UI. Главный экран показывает только пять физических LCD и параметры подключения. Библиотека и редактор открываются поверх него по запросу и не занимают постоянное место.

## Реализовано

- компактное WPF-окно фиксированного размера в Discord-подобной тёмной палитре, полностью без системной рамки и resize-border;
- пять пустых экранов с понятной кнопкой `+` при первом запуске;
- встроенный каталог GPU, CPU, CORE, RAM, SYSTEM, SMALL CLOCK и пустого CUSTOM WIDGET;
- реальные CPU/GPU/RAM-значения в preview только во время работы окна;
- квадратные preview 125×125, соответствующие физическим LCD;
- выбор всегда назначается на тот экран, по которому был сделан клик;
- шестерёнка в углу открывает заголовок, три строки датчиков, цвета рамки/текста и значок заголовка;
- набор оригинальных текстовых значков `$`, `:)`, `;)` и `>_`;
- компактное HSV-меню цвета с полем оттенка/насыщенности/яркости, выровненными HEX/R/G/B полями и шестью пресетами;
- переключатель `123 % / BAR` для поддерживаемых процентов;
- полупрозрачная неактивная шестерёнка у виджетов без настройки;
- последний элемент каталога импортирует PNG, JPG, JPEG, BMP или GIF;
- статические изображения автоматически обрезаются до 128×128 и кодируются в GIF для Times Gate;
- анимированный GIF масштабируется покадрово до 128×128 с сохранением задержек и бесконечного цикла;
- локальное JSON-сохранение раскладки без LocalToken;
- `CLEAR ALL` возвращает пять пустых экранов;
- `APPLY CHANGES` запускает Kestrel, аппаратный polling и последовательно назначает экраны;
- повторное применение отправляет только изменённые экраны, использует стабильные ID 1–15 и ждёт запрос фона и первого текста;
- `APPLY SCREEN` применяет только выбранный LCD для безопасной проверки прошивки;
- физические load-поля обновляются раз в 5 секунд, остальные стандартные поля — раз в 10 секунд, чтобы уменьшить постоянную нагрузку на прошивку;
- SMALL CLOCK использует нативный элемент прошивки `HourMinute`/`HourMinuteSecond`, документированный font 42 и ручное центрирование; секунды переключаются в настройках и не опрашивают веб-сервер ПК;
- в список строк добавлен компактный виджет даты `DATE: dd.MM.yyyy`;
- статус `READY`, `APPLYING`, `LIVE` или `ERROR`;
- manifest `asInvoker`; приложение запускается без UAC, а недоступные низкоуровневые CPU-датчики отображаются как `--`.

## Ограничения прототипа

- LocalToken не сохраняется;
- после покадрового масштабирования GIF должен занимать не более 2 MB и содержать не более 300 кадров;
- адрес локального сервера нельзя менять после первого успешного запуска без перезапуска окна;
- приложение должно оставаться открытым, иначе часы сохранят последние значения без обновлений;
- tray, автозапуск, reconnect, удаление старых импортированных файлов и файловые логи относятся к следующим итерациям;
- для импортированного изображения Times Gate выполняет редкий контрольный запрос раз в 300 секунд; это снижает нагрузку на прошивку, но длительный тест анимированного GIF всё ещё обязателен.

## Проверка

1. Запустить `artifacts/stage-2-final/TimesGateMonitor.UI.exe`; приложение не должно запрашивать UAC.
2. Ввести LocalToken.
3. Нажать первый пустой экран и выбрать GPU или CPU.
4. Открыть шестерёнку, поменять одну строку и при необходимости её режим `123 % / BAR`.
5. Нажать `APPLY SCREEN` и проверить только первый физический LCD.
6. Заполнить оставшиеся экраны и нажать `APPLY CHANGES`.
7. Дождаться зелёного статуса `LIVE` и сверить физические дисплеи с preview.

Порт локального HTTP-сервера — `8765`. Если он занят старым CLI-процессом, UI покажет ошибку. Процесс следует закрывать только после подтверждения пользователя, штатно через `Ctrl+C`.
