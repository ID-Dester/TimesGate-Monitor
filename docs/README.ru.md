# TGm — монитор ПК для Divoom Times Gate

> Неофициальный монитор для Divoom Times Gate.  
> Проект не связан с Divoom и не одобрен компанией Divoom.

TGm — открытое Windows-приложение, которое выводит данные CPU, GPU и RAM на пять экранов Divoom Times Gate. Изменяемые значения передаются как сетевой текст, поэтому при обычном обновлении датчиков часы не загружают новую картинку.

## Статус

Проект готовится к первому публичному preview-релизу. До стабильного релиза сборки следует считать тестовыми.

> [!WARNING]
> **Известная проблема перезапуска устройства:** в некоторых длительных сессиях Network Text Times Gate возвращался к стандартному циферблату примерно после **35 000 запросов, посчитанных локальным сервером TGm**. Другие многочасовые тесты проходили без отказа. Точный порог и первопричина не доказаны, а ответ HTTP 200 не подтверждает, что LCD корректно отрисовал данные. TGm обнаруживает длительное отсутствие запросов от экранов и пытается восстановить dashboard, но не может предотвратить событие на стороне устройства. Перед установкой preview прочитайте раздел [«Известные проблемы»](KNOWN-ISSUES.md#times-gate-may-restart-or-return-to-a-stock-clock-face-during-long-sessions).

## Возможности

- пять независимо настраиваемых экранов с честным preview 125×125;
- пресеты GPU, CPU, CORE, RAM, SYSTEM и SMALL_CLOCK;
- пустой CUSTOM_WIDGET и импорт PNG, JPG, BMP и анимированного GIF;
- настройка рамки, текста, заголовка и строк значений;
- tray, автозапуск, запуск свёрнутым, пауза и переподключение;
- пассивный контроль каждого LCD и восстановление только сброшенного экрана;
- необязательный sensor host для температуры, мощности и частоты CPU;
- хранение LocalToken в Windows Credential Manager, а не в JSON или логах.

FPS намеренно не входит в первый публичный релиз.

## Требования

- Windows 10/11 x64;
- Times Gate и ПК в одной локальной сети;
- IPv4-адрес устройства и LocalToken из мобильного приложения Divoom;
- PawnIO, если конкретному CPU нужен низкоуровневый доступ к расширенным датчикам.

Основной интерфейс всегда работает без прав администратора. CPU load имеет обычный Windows fallback. Расширенные CPU-датчики включаются отдельно и требуют одного подтверждения UAC для регистрации `TGm.SensorHost`.

## Первый запуск

1. Запустите TGm обычным способом, не от администратора.
2. Введите IP Times Gate, LocalToken и LAN IPv4 этого ПК.
3. Выберите виджет для одного экрана и нажмите **APPLY SCREEN**.
4. После успешной проверки настройте остальные экраны и нажмите **APPLY CHANGES**.
5. Откройте настройки кнопкой-шестерёнкой и включайте **CPU SENSOR ACCESS** только при необходимости.

Times Gate получает значения с TCP-порта `8765` на ПК. VPN или firewall, фильтрующие LAN-трафик, могут потребовать отдельное исключение. TGm не отправляет телеметрию в облако.

## Сборка из исходников

```powershell
dotnet restore TimesGateMonitor.sln
dotnet build TimesGateMonitor.sln -c Release --no-restore
dotnet run --project tests/TimesGateMonitor.Tests -c Release --no-build
dotnet run --project src/TimesGateMonitor.App -c Release --no-build
```

Release-архив создаётся командой:

```powershell
.\scripts\Build-Release.ps1 -Version 0.1.0-preview.1
```

По умолчанию это self-contained Windows x64 ZIP со встроенным .NET runtime, sensor host, лицензиями, безопасным скриптом удаления и SHA-256. GitHub Actions дополнительно собирает per-user установщик Inno Setup. Пока у проекта нет сертификата подписи кода, Windows SmartScreen может показывать предупреждение о неизвестном издателе; перед запуском preview следует сверить SHA-256.

## Данные и безопасность

- настройки и логи: `%LOCALAPPDATA%\TGm`;
- раскладка и импортированные файлы: `%LOCALAPPDATA%\TimesGateMonitor`;
- LocalToken: Windows Credential Manager, запись `TGm/TimesGateMonitor/LocalToken`.

Не прикладывайте LocalToken к issue или диагностике. Код TGm распространяется по MIT; лицензии зависимостей перечислены в [THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md).
