# Stage 3: background reliability

Статус: preview с опциональным sensor host готов к проверке на реальном устройстве.

## Добавлено

- бренд `TGm — PC Monitor for Divoom Times Gate` и дисклеймер в настройках;
- полностью удалена графика Helldivers; старое значение `helldiver` мигрирует в `terminal`;
- запуск от текущего пользователя через `asInvoker`;
- один экземпляр TGm на пользователя;
- notification area icon с командами Open, Pause, Reconnect, Open logs и Exit;
- сворачивание и закрытие в tray;
- автозапуск через `HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Run`, без администратора;
- запуск сразу в tray через настройку или аргумент `--background`;
- отдельный пассивный heartbeat каждого LCD: в нормальном режиме TGm не отправляет Times Gate служебную команду каждые 15 секунд;
- после 90 секунд без запросов TGm проверяет устройство и восстанавливает только сброшенный LCD;
- пятиминутный cooldown защищает часы от циклической повторной настройки одного экрана;
- exponential reconnect 5/10/20/30 секунд используется только после подтверждённой потери устройства;
- безопасная сериализация Apply через `SemaphoreSlim`;
- перезапуск локального HTTP-сервера при изменении LAN IP без перезапуска TGm;
- rolling log `tgm.log`, до 2 MB и четыре архивных файла;
- локальные настройки в `%LOCALAPPDATA%\\TGm\\preferences.json`;
- FPS удалён с пользовательского SYSTEM-экрана и заменён локальным временем.
- CPU load получает непривилегированный fallback через Windows `GetSystemTimes`, если LibreHardwareMonitor не отдаёт CPU Total;
- подтверждено ограничение PawnIO: ACL устройства разрешает доступ только `SYSTEM` и администраторам, поэтому CPU temperature/power/clock нельзя надёжно получить прямо из `asInvoker`-процесса.
- добавлен `TGm.SensorHost` с однократной добровольной регистрацией через UAC;
- при отказе CPU load продолжает работать, а temperature/power/clock отображаются как `--`;
- зарегистрированный sensor host запускается через Task Scheduler без повторного UAC, обслуживает только SID текущего пользователя и завершается после двух минут без запросов;
- в настройках по кнопке-шестерёнке можно позднее включить или удалить CPU sensor access;
- пустой LocalToken блокирует Apply, подсвечивает поле и показывает встроенную инструкцию.
- после успешного Apply LocalToken сохраняется как Generic Credential текущего пользователя в Windows Credential Manager; конфигурационный JSON и логи его не содержат;
- регистрация sensor host явно использует SID текущего пользователя и проверяет рабочий named-pipe ответ перед объявлением установки успешной.

LocalToken сохраняется только в памяти текущего процесса и не записывается в JSON или лог.

## Проверка Fan Control

Fan Control закрывать не нужно. Провести два прохода:

1. Запустить Fan Control, затем TGm. Применить dashboard и дать CPU/GPU нагрузку на 30–60 минут.
2. Завершить TGm через tray, оставить Fan Control работающим, снова запустить TGm и повторить нагрузку.

В обоих проходах проверить:

- кривые и RPM в Fan Control продолжают обновляться;
- TGm получает CPU load (включая Windows fallback), GPU temperature/load/power и RAM;
- CPU temperature/power/clock в обычном процессе отображаются как `--` до появления отдельного sensor service;
- нет зависаний PawnIO, скачка CPU usage или повторных UAC-запросов;
- в `%LOCALAPPDATA%\\TGm\\Logs\\tgm.log` нет повторяющихся hardware errors.

## Проверка reconnect

1. Выполнить полный `APPLY CHANGES`.
2. Вернуть один LCD на стандартный циферблат Divoom, не меняя остальные экраны.
3. Не нажимать Apply и дождаться 90–120 секунд.
4. TGm должен выполнить одну проверку устройства и восстановить только сброшенный LCD.
5. Для общей проверки временно разорвать LAN-соединение, вернуть устройство в сеть и убедиться, что экраны восстанавливаются последовательно, а не одной пачкой команд.

После этого нужен непрерывный тест 12–24 часа. До его прохождения сборка остаётся preview, а не final.

## Решение для низкоуровневых CPU-датчиков

TGm не повышает права всего WPF-приложения и не ослабляет ACL PawnIO. Опциональный `TGm.SensorHost.exe` регистрирует персональную задачу с highest privileges после одного подтверждения UAC. UI получает только сериализованный read-only `HardwareSnapshot` через named pipe с `CurrentUserOnly`; команд записи или управления железом в протоколе нет.

В локальной серии из 10 запросов с частотой 1 Гц sensor host использовал 31.7 MB private memory / 64.2 MB working set и в среднем 0.148% общей загрузки проверенного 16-thread CPU. Это примерно 2.36% одного логического ядра во время опроса; на бюджетном четырёхпоточном CPU ориентир составляет около 0.6% общей загрузки. После закрытия TGm и двух минут простоя процесс завершается, поэтому постоянная фоновая нагрузка отсутствует.
